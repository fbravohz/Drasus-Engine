### **ADR-0160: Internacionalización desde el Día Uno — Cero Cadenas Hardcodeadas en la UI, Capa de Localización, Español e Inglés de Base**

*   **Decisión:**
    Toda cadena visible al usuario pasa por una **capa de localización desde el primer día**; está prohibido escribir texto literal de interfaz dentro de un widget. Los idiomas base son **español e inglés**, mantenidos a la par. Agregar un idioma nuevo = agregar un archivo de recursos de traducción, **sin tocar código**. Se usa el mecanismo estándar de Flutter (archivos de recursos por idioma vía `flutter_localizations`/`intl`, generación de claves), no un sistema propietario.

*   **Objetivo (problema que resuelve):**
    GREENFIELD es el único momento barato para fijar esto. Retrofittear internacionalización sobre una UI con cientos de cadenas ya incrustadas es de los trabajos más dolorosos y masivos que existen. El propietario no quiere software clavado a un idioma; quiere facilidad para sumar idiomas, con español e inglés como los principales.

*   **Reglas (Restricciones — lo que NUNCA puede pasar):**
    - **Cero Cadenas Hardcodeadas (FIJO):** ningún texto visible al usuario se escribe literal en el widget — siempre se referencia por su clave de localización. Es un invariante de UI, no una preferencia.
    - **Paridad de Idiomas Base (FIJO):** español e inglés se mantienen con el mismo conjunto de claves; una clave nueva nace en ambos.
    - **Agregar Idioma = Agregar Archivo (FIJO):** incorporar un idioma es soltar un archivo de recursos nuevo, sin cambios de código.
    - **El Backend No Localiza Prosa (FIJO):** el núcleo Rust emite **códigos de error/estado estables**, no frases traducidas; la UI es la única que convierte código → prosa localizada. Evita que la lógica de negocio hornee un idioma.
    - **Formato Local vs. Almacenamiento (FIJO):** fechas, números y moneda se **muestran** según el locale del usuario, pero el almacenamiento y el reloj interno siguen en UTC y escala entera (no se altera lo ya fijado sobre representación interna). Display ≠ storage.

*   **Efecto observable (sin código):**
    - El usuario cambia el idioma en ajustes y toda la interfaz cambia de inmediato.
    - Un colaborador agrega un idioma nuevo soltando un archivo de traducción; no toca código.
    - Un mensaje de error del motor aparece en el idioma del usuario, aunque el motor solo emitió un código.

*   **Costo (trade-off real):**
    Disciplina desde el día uno: cada cadena nueva pasa por su clave. Es barato ahora (mientras la UI se construye) y carísimo si se deja para después. Es un impuesto pequeño y constante que compra un mercado global sin reescritura.
